# Formula Studio

เครื่องมือ R&D Briefing ของ **Beyond Laboratory** — รวมงานตั้งแต่รับบรีฟจากลูกค้า → สร้างชุดข้อมูลงาน → คุยและอนุมัติในห้องแชท → ปิดงาน ไว้ในหน้าเดียว

## ใช้งาน

เปิดไฟล์ `index.html` ด้วยเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งหรือ build อะไรทั้งสิ้น

## ความสามารถหลัก

- **หน้าเข้าใช้งาน (Login)** — ครอบทั้งจอจนกว่าจะล็อกอินสำเร็จ ใช้ชื่อผู้ใช้หรืออีเมลบริษัท + รหัสผ่าน
- **Customer Data** — ฟอร์มบันทึกบรีฟลูกค้า (ลูกค้า & แบรนด์, รายละเอียดสินค้า, ลักษณะสินค้า & บรรจุภัณฑ์, กลุ่มเป้าหมาย & ราคา, สรรพคุณ / ข้อจำกัด / หมายเหตุ) พร้อมสูตรส่วนผสม
  ในส่วน **ลูกค้า & แบรนด์** มีช่อง **ตลาดปลายทาง** (Domestic / Oversea) และ **ประเทศปลายทาง** — ช่องประเทศจะกรอกได้ก็ต่อเมื่อเลือก Oversea (เลือก Domestic ระบบจะล้างชื่อประเทศให้เอง)
  เลือก **Oversea** แล้ว **ต้องระบุประเทศปลายทางก่อน จึงจะกดสร้างชุดข้อมูลได้** (ไม่ระบุจะขึ้นเตือนและกรอบช่องเป็นสีแดง ข้อมูลที่กรอกไว้ไม่หาย)
  งานที่เป็น **Oversea** จะแสดง **เลขงานเป็นสีส้ม** ทุกที่ (เมนูซ้าย · ตาราง Dashboard · หัวห้องแชท · ป๊อปอัพรายละเอียด · รายการใน PD Modify Data)
  กด **สร้างชุดข้อมูล** แล้วฟอร์มจะถูกล้างเป็นว่างทันที พร้อมกรอกงานใบใหม่ (ข้อมูลที่กรอกไปเก็บอยู่ในรหัสงานแล้ว เปิดกลับมาแก้ได้จาก Dashboard)
- **Dashboard** — สรุปงานทั้งหมด, งานที่ปิดแล้ว, งานที่ถูก Reject, ค้นหา / กรอง / Export Excel
- **Tag** — จัดกลุ่มงานด้วยป้ายสี ตั้งชื่อและเลือกสีเองได้ **สูงสุด 30 Tag** · 1 งานติดได้หลาย Tag
  แสดงเป็นจุดสีต่อท้ายรหัสงานในเมนูซ้าย และเป็นป้ายชื่อในตาราง Dashboard
  มีตัวกรอง **Tag** ในหน้า Dashboard (เลือกได้ทั้ง Tag ใด Tag หนึ่ง หรือ "ยังไม่ติด Tag")
  **เมนูซ้ายใต้ Chat Message** จัดกลุ่มตาม Tag — กดชื่อ Tag เพื่อกาง/พับรายการรหัสงานในกลุ่มนั้น
  งานที่ติดหลาย Tag จะอยู่ใต้ทุก Tag ที่ติดไว้ · งานที่ยังไม่ติดอยู่ในกลุ่ม "ยังไม่ติด Tag" ท้ายสุด
  สร้าง/ลบ Tag ที่ปุ่ม **จัดการ Tag** · ติด Tag ได้ทั้งจากห้องแชท และจากหน้า Dashboard โดยตรง
  **ในตาราง Dashboard:** กด **+ Tag** เพื่อติด · กด **×** บนป้ายเพื่อถอด
  **ทำทีละหลายงาน:** ติ๊กช่องหน้าแถว (หรือติ๊กหัวตารางเพื่อเลือกทั้งหมดที่ตัวกรองแสดงอยู่) แล้วกด **ติด / ถอด Tag**
  สิทธิ์: Admin · Sales · Oversea · OPC · MKT (เท่ากับสิทธิ์สร้างชุดข้อมูล) · ลบ Tag แล้วจะถูกถอดออกจากงานเอง แต่ตัวงานไม่ถูกลบ
  **Role Sales / Oversea เห็นและใช้ได้เฉพาะ Tag ที่ตนเองสร้าง** — Tag ของคนอื่นถูกซ่อนทั้งในเมนูซ้าย ตาราง ตัวกรอง และป๊อปอัพเลือก Tag
  (ติด/ถอด/ลบ ก็ทำกับ Tag ของคนอื่นไม่ได้) · Role อื่นเห็นครบทุก Tag · Tag เก่าที่สร้างไว้ก่อนมีกติกานี้ถือเป็นของกลาง ทุกคนยังใช้ได้
- **Reject** — Sales เจ้าของงาน (หรือ Admin) กด Reject จากห้องแชทเพื่อตีงานกลับ
  งานจะย้ายเข้าการ์ด **Reject** ในหน้า Dashboard และหายจากเมนูซ้าย
  ⚠️ **Reject แล้วยกเลิกไม่ได้** — งานนั้นถือว่าจบ (มีถามยืนยันก่อนเสมอ)
- **Chat Message** — ห้องแชทต่อ 1 งาน พร้อมประวัติการแก้ไขชุดข้อมูล และการอนุมัติ 4 ฝ่าย (PD / RA / RD / Sales)
- **เลขงานในเมนูซ้ายเป็นเขียวเข้มเมื่อ "ฝ่ายของเรา" Pass แล้ว** — PD เห็นเขียวเมื่อ PD Pass, RA เมื่อ RA Pass,
  RD เมื่อ RD Pass, Sales/Oversea เมื่อ Sales Pass · Admin (อนุมัติได้ทุกฝ่าย) เขียวเมื่อครบทั้ง 4
  Role ที่ไม่มีหน้าที่อนุมัติ (OPC · Purchasing) ไม่มีสีเขียว · ถอน Pass ออกแล้วกลับเป็นสีเดิมทันที
  ⚠️ งานที่ตลาดเป็น **Oversea** ยังเป็น**สีส้ม**เสมอ (กฎเลขงานสีส้มมาก่อน) ดูสถานะ Pass ของตัวเองได้จาก tooltip และตัวเลข x/4
- **ถอน Pass ฝ่ายใดฝ่ายหนึ่ง = Pass ของทุกฝ่ายในงานนั้นถูกล้างทั้งหมด** ทุกฝ่ายต้องกลับมาอนุมัติใหม่
  (Pass ที่ฝ่ายอื่นให้ไว้อ้างอิงข้อมูลชุดเดิมที่กำลังจะถูกแก้ ถ้าปล่อยไว้จะกลายเป็นการอนุมัติของที่ยังไม่ได้ตรวจ)
  มีถามยืนยันก่อนเสมอ พร้อมบอกว่าจะล้าง Pass ของฝ่ายไหนบ้าง · ลงบันทึกทั้งในแชทและ Activities log
- **Export Excel** — 2 ชีต: **ชุดข้อมูล** (46 คอลัมน์) และ **สูตร ส่วนผสม** (9 คอลัมน์)
  ครบทุกฟิลด์ของงาน รวมจุดขาย · ผู้แก้ไขล่าสุด · บันทึกหลังปรับสูตร · ผู้อนุมัติทั้ง 4 ฝ่ายพร้อมเวลา · สถานะปิดงาน/Reject · สารหลัก (⭐) · ตลาด/ประเทศปลายทาง
- **ประวัติเวอร์ชัน & กู้คืน** — ทุกครั้งที่ข้อมูลงานเปลี่ยน (ไม่ว่าจะแก้เอง หรือถูกซิงก์ทับ) ระบบเก็บ **ตัวเดิม** ไว้ให้อัตโนมัติ
  เปิดดูที่ปุ่ม **ประวัติเวอร์ชัน** ในป๊อปอัพรายละเอียดงาน แล้วกด **กู้คืน** ได้ทันที (Admin · PD · MKT)
  เก็บ 12 เวอร์ชันล่าสุดต่องาน **ในเครื่องที่แก้เท่านั้น** ไม่ขึ้นเซิร์ฟเวอร์ · กู้คืนแล้วเวอร์ชันที่ทิ้งไปก็ยังกู้กลับได้อีก
- **เบรกฉุกเฉินกันเขียนทับหมู่** — ถ้าเครื่องไหนกำลังจะเขียนทับ **สูตร** ของงานเกิน 3 ใบพร้อมกัน ระบบจะ**หยุดไว้ก่อน**
  แล้วขึ้นแถบแดงให้เลือกว่า *ใช้ข้อมูลล่าสุดจากเซิร์ฟเวอร์* หรือ *ยืนยันส่งข้อมูลของเครื่องนี้*
  (ระหว่างนั้นแชท / การอนุมัติยังซิงก์ตามปกติ · เลือกทางไหนของอีกฝั่งก็ยังอยู่ในประวัติเวอร์ชัน)
- **Activities log** — บันทึกทุกการกระทำในระบบ (Admin)
  ตารางสูงไม่เกิน 1 หน้าจอ เกินกว่านั้นเลื่อนอยู่ในตาราง (หัวตารางค้างไว้)
  หน้าจอตั้งต้นแสดงเฉพาะ **รายการของวันนี้** และเริ่มนับใหม่เองทุกเที่ยงคืน — **ข้อมูลเก่าไม่ถูกลบ** กด **ย้อนหลังทั้งหมด** หรือเลือกช่วงวันที่เพื่อดูย้อนหลัง
- **จัดการผู้ใช้** — เพิ่ม / แก้ไข Role / รีเซ็ตรหัสผ่าน (Admin)
- **สวมบทบาทผู้ใช้** — เข้าใช้งานในมุมมองของ Role อื่นเพื่อตรวจสอบสิทธิ์ (Admin ตัวจริงเท่านั้น)
- **ออกจากระบบ** — เมนูล่างสุดของแถบซ้าย ยืนยันก่อนออก แล้วกลับไปหน้า Login

## Role

`Admin` · `PD` · `RA` · `RD` · `Sales` · `Oversea` · `OPC` · `MKT` · `Purchasing`

สิทธิ์ทั้งหมดนิยามอยู่ที่ตัวแปร `ROLES` ในไฟล์ และตรวจผ่าน `can()` / `requirePerm()`

### เมนูไหนใครเห็น

| เมนู | Role ที่เข้าถึงได้ |
|---|---|
| Dashboard · Chat Message | ทุก Role |
| Customer Data | Admin · Sales · Oversea · OPC · MKT |
| Activities log | Admin |
| สวมบทบาทผู้ใช้ | Admin (และต้องไม่ได้สวมบทบาทอยู่) |
| จัดการผู้ใช้ | Admin (และต้องไม่ได้สวมบทบาทอยู่) |
| ปุ่ม Reject ในห้องแชท | Admin · Sales/Oversea/MKT ที่เป็นเจ้าของงานนั้น (ผู้สร้าง หรือ Sales ผู้รับผิดชอบ) |
| ปุ่ม Export Excel ในห้องแชท | Admin · Oversea · OPC · MKT (และต้องอนุมัติครบ 4 ฝ่ายก่อน) |

Role **MKT** มีสิทธิ์เท่ากับ **Sales + PD** รวมกัน — สร้างงาน · แก้สูตรและชุดข้อมูล · อนุมัติทั้ง PD และ Sales · **Export Excel** · ปิดงาน
(เห็นงานของทุกคน ไม่ถูกจำกัดให้เห็นเฉพาะงานตัวเองเหมือน Sales)

Role **Oversea** มีสิทธิ์เท่ากับ **Sales** ทุกข้อ แล้วเพิ่ม **Export Excel** — สร้างงาน · คุยในแชท · อนุมัติ Sales Pass · ปิดงาน · Reject งานของตนเอง · ส่งออกไฟล์
**และยังเห็นเฉพาะงานของตนเองเหมือน Sales** — ส่งออกได้เฉพาะงานที่ตนเองเห็นเท่านั้น

## รหัสผ่าน

- ผู้ใช้ทุกคนต้องมีรหัสผ่าน — บัญชีที่ยังไม่เคยตั้ง จะใช้รหัสตั้งต้น `123456` แล้วระบบบันทึกให้ถาวรตั้งแต่ล็อกอินครั้งแรก
- Admin รีเซ็ตรหัสของใครก็ได้ (ทีละคนหรือทั้งหมด) กลับเป็น `123456` ที่เมนู **จัดการผู้ใช้**
- ผู้ใช้เปลี่ยนรหัสของตัวเองได้ที่เมนู **เปลี่ยนรหัสผ่าน**
- ⚠️ รหัสผ่านเก็บเป็นค่าแฮชฝั่งเบราว์เซอร์ (`pwHash`) เป็นการกันคนอ่านผ่าน ๆ **ไม่ใช่ระบบความปลอดภัยระดับสูง**

## ข้อมูล

เก็บใน `localStorage` ของเบราว์เซอร์เสมอ และถ้าตั้งค่าเซิร์ฟเวอร์กลางไว้ จะซิงก์ให้ทุกเครื่องเห็นข้อมูลชุดเดียวกัน
**ก่อนแก้ไขโค้ด อ่าน [CLAUDE.md](CLAUDE.md) ก่อน — โดยเฉพาะกฎข้อ 1: ห้ามแก้ไขโครงสร้างข้อมูล**

## ตั้งค่าซิงก์ข้อมูลข้ามเครื่อง (Supabase)

ถ้าไม่ตั้งค่า แอปยังใช้งานได้ปกติ แต่ข้อมูลจะอยู่แค่ในเครื่องที่กรอก ไม่มีใครเห็นด้วย

1. สมัคร https://supabase.com (ฟรี) → **New project** → ตั้งชื่อ เช่น `beyond-formula` → เลือก region **Southeast Asia (Singapore)**
2. เข้าเมนู **SQL Editor** → **New query** → วางทั้งไฟล์ [supabase/schema.sql](supabase/schema.sql) → กด **Run**
3. เข้า **Project Settings → Data API** คัดลอก **Project URL** และ **anon public key**
4. เปิด `index.html` แก้ 2 บรรทัดบนสุดของแท็ก `<script>`
   ```js
   let SB_URL = 'https://xxxxxxxx.supabase.co';
   let SB_KEY = 'eyJhbGciOi...';
   ```
5. push ขึ้น GitHub → Vercel deploy เอง → เปิดเว็บ จะเห็นป้าย **ซิงก์แล้ว** สีเขียวมุมขวาบน

### การซิงก์ทำงานยังไง
- **เขียน:** ส่งขึ้นเซิร์ฟเวอร์เฉพาะรายการที่เปลี่ยนจริง (รวบการบันทึกที่ติดกันภายใน 0.15 วินาทีเป็นครั้งเดียว)
  เทียบว่า "เปลี่ยนจริงไหม" ด้วยการเรียงคีย์ก่อน เพราะ Postgres เก็บ jsonb แล้วเรียงคีย์ใหม่เอง
- **อ่าน:** จังหวะปรับตามการใช้งาน เพื่อให้ไวตอนคุยกันและเบาตอนไม่มีใครทำอะไร

  | สถานการณ์ | รอบดึงข้อมูล |
  |---|---|
  | เปิดห้องแชทค้างไว้ หรือมีความเคลื่อนไหวใน 1 นาทีล่าสุด | **3 วินาที** |
  | เงียบเกิน 1 นาที | 10 วินาที |
  | เงียบเกิน 5 นาที | 30 วินาที |
  | สลับไปแท็บอื่น | หยุดจนกว่าจะกลับมา |

  กลับไปรอบ 3 วินาทีทันทีเมื่อ: พิมพ์/กดอะไรก็ตาม · เปิดห้องแชท · กลับมาที่แท็บ · มีข้อมูลใหม่เข้ามา
  และดึงข้อมูลทั้งหมดทุก 1 นาทีเพื่อจับรายการที่ถูกลบ
- **เน็ตหลุด:** ใช้ข้อมูลในเครื่องต่อได้ ป้ายสถานะเป็นสีแดง พอเน็ตกลับมาจะซิงก์ให้เอง
- **ครั้งแรก:** ถ้าเซิร์ฟเวอร์ยังว่างและเครื่องมีข้อมูลอยู่ ระบบจะยกข้อมูลชุดนั้นขึ้นไปตั้งต้นให้อัตโนมัติ

### ใช้งานพร้อมกันหลายคน
- **เลขงาน** ออกจากเซิร์ฟเวอร์แบบ atomic (`fs_next_rec_seq`) สองคนกดสร้างพร้อมกันไม่มีทางได้เลขซ้ำ
- **ข้อความแชท** เก็บทีละข้อความ (`fs_messages`) และ **สถานะอนุมัติ** เก็บทีละฝ่าย (`fs_approvals`)
  ส่งพร้อมกันได้โดยไม่มีใครถูกทับ
- **สิ่งที่แก้ในเครื่องแล้วยังส่งขึ้นไม่เสร็จ จะไม่ถูกของเก่าจากเซิร์ฟเวอร์ทับ** — รอบดึงข้อมูลจะข้ามงานใบนั้นไว้ก่อน
  แล้วส่งของเราขึ้นในรอบถัดไป (เดิม PD แก้สูตรแล้วเจอข้อมูลเด้งกลับเป็นของเดิมที่ Sales ลงไว้)
- **ยังเหลือ:** สองคนแก้ชุดข้อมูลงานใบเดียวกันในนาทีเดียวกัน คนที่บันทึกทีหลังจะชนะทั้งใบ
- ถ้าเซิร์ฟเวอร์ยังไม่ได้รัน `schema.sql` เวอร์ชันใหม่ แอปจะถอยไปใช้วิธีเดิมให้เองโดยไม่พัง

### แก้สูตรแล้วไม่หาย
- **ปุ่ม "บันทึกสูตร"** อยู่ใต้ตารางสูตรทั้งในห้องแชทและหน้า PD Modify Data
  อ่านค่าจากทุกช่องตรง ๆ จึงบันทึกได้ทันทีโดยไม่ต้องออกจากช่องก่อน
- ยัง**บันทึกให้อัตโนมัติ**ทุกครั้งที่ออกจากช่องเหมือนเดิม ปุ่มเป็นตัวช่วยยืนยัน ไม่ใช่เงื่อนไข
- **ค่าที่พิมพ์ค้างไว้ไม่หายเมื่อหน้าจอถูกวาดใหม่** — รอบซิงก์ที่วิ่งทุก 3 วินาทีเคยล้างสิ่งที่กำลังพิมพ์ทิ้ง
  ตอนนี้ทั้งค่าที่พิมพ์ ตำแหน่งเคอร์เซอร์ และโฟกัส ถูกคืนกลับให้ครบ
- **กด Tab ไล่ช่องต่อกันได้ไม่สะดุด** — เดิมการบันทึกช่องแรกวาดตารางใหม่ทันที ช่องที่ Tab เข้าไปจึงถูกทิ้ง
  แล้วสิ่งที่พิมพ์ต่อหายทั้งหมด ตอนนี้เลื่อนการวาดใหม่ออกไปหลังเบราว์เซอร์ย้ายโฟกัสเสร็จแล้ว
- **แถวที่ยังไม่ได้บันทึกขึ้นพื้นสีเหลือง** และปิดหน้าต่างทั้งที่ยังมีของค้างจะมีคำเตือนก่อน
- ทุกการเปลี่ยนแปลงยังถูกบันทึกเป็นข้อความในแชท + Activities log และเก็บเวอร์ชันก่อนหน้าไว้กู้คืนได้

### คุยกันสองคนขึ้นไปในห้องเดียว
- **กำลังพิมพ์อยู่แล้วมีข้อความเข้า** — ข้อความในช่องพิมพ์ ตำแหน่งเคอร์เซอร์ และโฟกัส ยังอยู่ครบ
- **เลื่อนขึ้นไปอ่านย้อนหลัง** — จอไม่ดีดลงล่าง จะเลื่อนตามข้อความใหม่เฉพาะตอนที่อยู่ท้ายห้องอยู่แล้ว
- **กดส่งตอนที่รอบซิงก์กำลังวิ่ง** — เข้าคิวส่งต่อทันทีที่รอบนั้นจบ ไม่ถูกทิ้ง
- **เวลาของข้อความ** อ้างอิงนาฬิกาเซิร์ฟเวอร์ เครื่องที่นาฬิกาเพี้ยนจะไม่ทำให้ลำดับข้อความสลับ
- **สองคนกดส่งพร้อมกันเป๊ะ ๆ** — ระบบเผื่อเวลาย้อนหลัง 15 วินาทีตอนดึงข้อมูล ข้อความที่บันทึกเสร็จเหลื่อมกันจึงไม่หลุด
- **กระดิ่งแจ้งเตือน** ห้องที่เปิดอ่านแล้วจะไม่กลับมาเด้งใหม่เองทุกนาที

### ⚠️ เรื่องความปลอดภัย
ระบบ login ยังตรวจฝั่ง client เหมือนเดิม และ anon key อยู่ในไฟล์ที่เปิดดูได้
**ใครที่รู้ URL ของเว็บสามารถดึงข้อมูลทั้งหมดได้** — เหมาะกับข้อมูลภายในทีมเท่านั้น
ถ้าต้องการกันจริงต้องเปลี่ยนไปใช้ Supabase Auth + RLS ตามผู้ใช้
